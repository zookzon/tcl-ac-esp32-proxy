# A5 Warm Rejoin / State Sync

This build adds Factory-style state re-acquisition after ESP32 boot/restart while the AC remains powered.

Evidence-backed sequence used:
- Factory Dongle startup INIT captured as `A5 01 00 21 03 00 00 0D 08 05 00 00 01`.
- Mediator V5 already proved forwarding this `00 00 01` INIT makes the TAC-PRO12PEC accept the transaction and return A5 responses/state reports.

Behavior:
1. 750 ms after ESP32 runtime boot, send the exact Factory-style INIT `00 00 01` to the AC.
2. CRC-16/XMODEM is generated by the existing A5 frame sender; generated CRC is `0x0805`, matching the captured Factory frame.
3. On the first valid `0C 0C` AC state report, mark rejoin successful and stop retrying.
4. 250 ms later, send one Factory-style `0B 0B FF FF` parameter/state query to request the full state set (used to resync persistent settings such as Beep).
4. If no `0C 0C` report arrives, retry after 2 seconds, up to 3 attempts total.
5. The `0B 0B FF FF` query is sent once only after rejoin; it does not replace or repeat the proven INIT handshake.
6. V5 mediator routing, Factory Dongle forwarding, Action AUTO/20-25 logic, Swing, Beep, RAW logger and other controls are unchanged.

Useful log tags: `A5-REJOIN`, `A5-PHASE2`, `A5-STATE-RAW` (when RAW logger is enabled).
